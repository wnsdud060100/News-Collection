# 뉴스 수집기 기능 개발 워크플로우

News Collection 앱에서 새 기능을 개발하기 위한 워크플로우입니다.
브랜치 이름: $ARGUMENTS

아래 단계를 순서대로 실행해줘. 각 단계가 끝나기 전에는 다음 단계로 넘어가지 마.

## 1단계: 현재 상태 확인

1. `git status`와 `git branch --show-current`로 현재 브랜치와 작업 트리 상태를 확인해.
2. 현재 브랜치가 `main`이 아니라면:
   - 현재 브랜치 이름을 알리며 경고해줘.
   - "main으로 이동할까요?"라고 물어보고 **사용자 답변을 기다려.** 답변 전에는 이동하지 마.
   - 승인하면 `git checkout main`으로 이동해. 거절하면 워크플로우를 중단해.
   - 커밋되지 않은 변경사항이 있어 이동이 막히면, 그 사실을 알리고 어떻게 할지 물어봐. 임의로 stash/삭제하지 마.

## 2단계: 새 브랜치 생성

1. `$ARGUMENTS`가 비어 있지 않으면 그 이름으로 `git checkout -b <이름>`을 실행해.
2. `$ARGUMENTS`가 비어 있으면:
   - 어떤 기능을 개발할 것인지 사용자에게 물어봐.
   - 답변을 바탕으로 **영어 소문자-하이픈 형식**의 브랜치 이름을 제안해. (예: `category-crud`, `notion-oauth`)
   - 사용자가 확인하면 그 이름으로 브랜치를 만들어.
3. 같은 이름의 브랜치가 이미 있으면 알리고 다른 이름을 물어봐.

## 3단계: 개발 시작 안내

1. 브랜치 생성이 끝나면 **"이제 개발을 시작하세요!"** 라고 안내해.
2. `CLAUDE.md`를 읽고 이 프로젝트의 기술 스택과 컨벤션을 다시 한번 알려줘:
   - 기술 스택 (Next.js, React, Tailwind, Clerk, Neon + Drizzle, Gemini, Notion MCP 등)
   - 명령어 (`npm run dev`, `npm run build`, `npm run lint`)
   - Next.js 버전 주의사항 (코드 작성 전 `node_modules/next/dist/docs/` 확인)
   - UI 작업 시 `ui.md` 참고, 충돌 시 `PRD.md`가 우선
   - 동작 규칙 요약 (모든 페이지/API 인증 필수, 피드 기반 분류, 서버 전용 키 등)
3. 안내 후에는 사용자가 개발을 진행하도록 기다려.

## 4단계: 완료 처리 (사용자가 '완료' 또는 'done'을 입력했을 때)

1. `git status`와 `git diff --stat`으로 변경된 파일 목록을 보여줘.
2. 변경 내용을 바탕으로 커밋 메시지를 제안해. 기존 커밋 이력(`git log --oneline`)의 스타일(한국어, 간결한 한 줄)을 따라.
3. 사용자에게 확인을 받아. 수정 요청이 있으면 반영해.
4. 확인을 받으면:
   - 변경 파일을 스테이징하고 커밋해. (`.env*` 등 비밀 정보가 포함된 파일은 제외하고, 의심되면 먼저 알려줘)
   - `git checkout main` 후 `git merge <브랜치-이름>`으로 병합해.
   - 병합 충돌이 나면 충돌 파일을 알리고 사용자와 해결 방법을 상의해. 임의로 해결하지 마.
5. `git push`나 브랜치 삭제는 사용자가 요청하기 전에는 하지 마.

## 5단계: 작업 요약

병합이 끝나면 다음을 요약해서 보여줘:
- 브랜치 이름과 병합 결과
- 커밋 메시지와 커밋 해시
- 변경된 파일 목록과 주요 변경 내용
- 다음에 할 만한 작업 (CLAUDE.md의 구현 순서 기준)
